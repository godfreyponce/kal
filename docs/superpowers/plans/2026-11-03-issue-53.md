# Assistant bubbles render markdown (#53) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Assistant chat bubbles show `**bold**`, `*italic*`, `` `code` `` and `- ` lists as formatting, not as literal markers, including while a reply streams.

**Architecture:** A pure parser, `parseChatMarkdown` in `lib/chat-markdown.ts`, turns the bubble text into a small tree of blocks (text runs and lists) and inline segments (text, bold, italic, code). A marker that has no closing partner stays literal text, so a reply cut off mid-`**` during streaming shows plain text until the closing `**` arrives. A small component, `ChatMarkdown` in `app/chat/chat-markdown.tsx`, maps that tree to React elements (`<strong>`, `<em>`, `<code>`, `<ul>`). React escapes all text, so model output never reaches the page as HTML. `app/chat/chat.tsx` uses the component only in the non-error `bub-ai` branch.

**Tech Stack:** Next 16, React 19, TypeScript, vitest (node environment, no DOM), plain CSS in `app/globals.css`, Playwright (already a dev dependency) for the gate-2 screenshot.

**Spec:** Issue #53 (`gh issue view 53`). The issue has no Done when section. The owner accepted the planner's proposed Done when and the three other recommendations on 2026-11-03 (reply: "agree all"). This plan records those decisions.

**Interfaces:**
- Produces, in `lib/chat-markdown.ts`:

```ts
export type Inline = { kind: "text" | "bold" | "italic" | "code"; text: string };
export type Block =
  | { kind: "text"; inline: Inline[] }
  | { kind: "list"; items: Inline[][] };
export function parseChatMarkdown(src: string): Block[];
```

- Produces, in `app/chat/chat-markdown.tsx`: `export function ChatMarkdown({ text }: { text: string })`.

**Parser rules** (the tests below pin each one):

- Blocks: split `src` on `\n`. A line that starts with `- ` is a list item (the item text is the rest of the line). Consecutive list lines form one `list` block. All other lines group into `text` blocks, joined back with `\n`. Empty lines directly before or after a list are dropped. `""` gives `[]`.
- Inline, scanning left to right:
  - `` ` ``: if a later `` ` `` exists and the content between is non-empty, emit `code`. Otherwise the backtick is literal.
  - `**`: if a later `**` exists and the content is non-empty, does not start with a space, and does not end with a space, emit `bold`. Otherwise `**` is literal and the scan continues after it.
  - `*` (single, not part of `**`): if the next character is not a space and a later single `*` exists whose previous character is not a space, emit `italic`. Otherwise the `*` is literal.
  - Everything else is text. Adjacent text segments merge into one.
- Content of `bold`, `italic` and `code` is plain text (no nesting).

- [ ] **Step 1: Write the failing tests** in `lib/chat-markdown.test.ts`

Shorthand in this list: `t(s)` is `{ kind: "text", text: s }`, `b(s)` bold, `i(s)` italic, `c(s)` code, and `para(...inline)` is `{ kind: "text", inline: [...] }`. Define these helpers in the test file.

- `empty string`: `parseChatMarkdown("")` → `[]`.
- `plain text`: `"Hi there"` → `[para(t("Hi there"))]`.
- `ticket reply`: `"Done. **Logged: Raising Cane's Caniac combo — 2000 kcal / 95P / 210C / 95F.**"` → `[para(t("Done. "), b("Logged: Raising Cane's Caniac combo — 2000 kcal / 95P / 210C / 95F."))]`.
- `italic and code`: ``"a *b* `c` d"`` → `[para(t("a "), i("b"), t(" "), c("c"), t(" d"))]`.
- `cut off mid-bold (streaming)`: `"Done. **Logged: Rai"` → `[para(t("Done. **Logged: Rai"))]`; and `"**Logged*"` → `[para(t("**Logged*"))]`; and `"**"` → `[para(t("**"))]`.
- `bold completes when its close arrives`: `"**Logged**"` → `[para(b("Logged"))]`.
- `cut off mid-code`: ``"use `kcal"`` → `[para(t("use `kcal"))]`.
- `lone and spaced asterisks stay literal`: `"2 * 3 = 6"`, `"5*2"`, and `"* item"` each give one `para` with one `t` equal to the input.
- `html stays text`: `"<b>hi</b>"` → `[para(t("<b>hi</b>"))]`.
- `newlines stay inside one text block`: `"one\ntwo\n\nthree"` → `[para(t("one\ntwo\n\nthree"))]`.
- `list between prose`: `"Here:\n- **a**\n- b\nDone"` → `[para(t("Here:")), { kind: "list", items: [[b("a")], [t("b")]] }, para(t("Done"))]`; and `"Here:\n\n- a\n\nDone"` → `[para(t("Here:")), { kind: "list", items: [[t("a")]] }, para(t("Done"))]`.
