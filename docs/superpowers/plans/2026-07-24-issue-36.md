# Collapse Meal plan and Memory sections by default (issue #36) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:build-ticket to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking. This is a **single-task** plan — per AGENTS.md it stays **uncommitted in the working tree** at gate 2 (no ticket branch, no per-task commits).

**Goal:** On `/plan`, the Meal plan and Memory sections render collapsed by default — only their header band (name, count, chevron) shows; tapping the band toggles the section, the chevron flips, and editor state survives the collapse. Adherence and Profile stay always-open.

**Architecture:** The page is a Server Component (async, reads live DB) so it cannot hold `useState`. Introduce one small Client Component, `CollapsibleSection`, that owns a `useState(false)` open flag, renders the existing `.plan-kick` band as a `<button aria-expanded>` with a chevron, and **keeps its children mounted**, hiding them with the `hidden` attribute when closed. Keeping children mounted (rather than conditionally rendering) is what preserves the meal editor's / memory form's React state across a collapse and across `router.refresh()`. The page wraps only `MealPlanEditor` and `MemoryList`; the Adherence and Profile bands are untouched.

**Tech Stack:** Next 16 App Router (Server Component page + one Client Component wrapper), React `useState`, CSS in `app/globals.css`.

- [ ] **Step 1: Create the client wrapper component**

Create `app/plan/collapsible-section.tsx` with exactly:

```tsx
// app/plan/collapsible-section.tsx
"use client";

import { useState, type ReactNode } from "react";

export function CollapsibleSection({
  title,
  meta,
  animationDelay,
  children,
}: {
  title: string;
  meta: string;
  animationDelay: string;
  children: ReactNode;
}) {
  const [open, setOpen] = useState(false);
  return (
    <>
      <button
        type="button"
        className="plan-kick plan-kick-btn anim"
        style={{ animationDelay }}
        aria-expanded={open}
        onClick={() => setOpen((o) => !o)}
      >
        {title}
        <span className="plan-kick-end">
          <small>{meta}</small>
          <span className="plan-chev" aria-hidden="true">▾</span>
        </span>
      </button>
      <div hidden={!open}>{children}</div>
    </>
  );
}
```

Notes for the implementer:
- The band reuses the existing `.plan-kick` class (so background, padding, radius, uppercase typography, and the caramel `small` are inherited unchanged) plus `.plan-kick-btn` to neutralize the `<button>` chrome. `.anim` + `animationDelay` preserve the enter stagger the old `<div className="plan-kick anim">` had.
- Children are hidden with the `hidden` attribute (`display:none` via the UA stylesheet) — they stay **mounted**, so the meal editor / memory form keep their state when the section is closed and reopened. Do **not** switch this to `{open && children}`; that would unmount and lose editor state (Done-when bullet 3).
- The chevron is `aria-hidden` because `aria-expanded` on the button already conveys the state to assistive tech.

Why only these properties: this repo has **no global button reset** (buttons are neutralized per-component). `.plan-kick` already supplies background, padding, radius, and every typographic property *except* `font-family`, which the button UA style would otherwise override — hence `font-family: inherit`. The rest strips the button's border/appearance/margin and makes it full-width and left-aligned so it looks identical to the old `<div>` band. The chevron rotates 180° when open; the transition is a plain transform (not the expand itself) and is nulled under reduced motion.

## Design decisions the owner should sanity-check at gate 1

1. **No expand animation (simplest reading of the reduced-motion bullet).** The Done-when says "Reduced-motion gets no animated expand, just show/hide" — a floor, not a mandate to animate the normal case. This plan does a plain `hidden` toggle in **both** modes, which is the least code and trivially satisfies the reduced-motion bullet. If the owner wants motion in the normal (non-reduced) case, the drop-in is a `grid-template-rows: 0fr → 1fr` transition on the content wrapper (robust, needs no height measuring, works with kept-mounted children), disabled under `prefers-reduced-motion`. Flagging because this is the bullet most open to interpretation.

2. **Tapping the band always collapses, even with an editor open — state is preserved, not blocked.** "A section with an open editor should not silently collapse" is read as *no collapse without user intent*; a deliberate tap is intent. So an open editor is hidden (not unmounted) on collapse and restored intact on reopen, rather than the tap being disabled while editing. If the owner instead wants the band to refuse to collapse while an editor is open, that's a small change (guard the toggle on an "is a child editing" signal), but it needs plumbing a flag up from `MealPlanEditor`/`MemoryList`, which this plan deliberately avoids.
