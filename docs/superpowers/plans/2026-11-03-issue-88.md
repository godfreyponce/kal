# Groceries delete refuses a food a saved Undo copy needs (#88) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You cannot delete a grocery while a saved Undo copy (`replaced_writes`) still references it, so Undo never fails on a missing food.

**Architecture:** `replaced_writes.food_ids` (`db/schema.ts:157-168`) has no foreign key. Live tables use FK `restrict` on `food_id`, and the DELETE route maps that error (Postgres code `23503`) to a 409. This plan adds the same refusal for saved copies. `deleteGrocery` (`lib/groceries.ts:186-189`) first checks whether any `replaced_writes` row has the food id in `food_ids`. If one does, it throws a new typed `FoodInUseError`. The route maps that error to the same 409 and the same message as the FK case. `lib/undo.ts` does not change.

**Tech Stack:** Next 16 route handlers, Drizzle ORM on Neon Postgres, Vitest against live Neon.

**Spec:** Issue #88 (`gh issue view 88`). Blocker #85 is closed. The issue has no comments. The Done when section says "Pick one at planning" about two options. This plan picks one, below.

## Planner decisions (gate 1, the owner confirms or changes)

- **Refuse the delete. Do not skip missing foods in Undo.** Done when gives two options. The plan picks "refuse". Reason: in the ticket's example, the saved copy A has only one line, grocery X. If Undo skips X, A restores as zero lines, and the meal shows the template. That is the same result the ticket calls a silent loss. With "refuse", the delete gets a 409, and Undo of B restores A in full. Cost: X stays undeletable until no saved copy references it. Past logs and past overrides already keep a used food undeletable, so this matches what the screen already does.
- **Every saved copy blocks, including Today-untap copies (`batch_id` null).** No Undo can restore a copy with a null `batch_id`, so it does not need its foods. Alternative: add `batch_id IS NOT NULL` to the check, so such copies do not block. The plan does not add it. Reason: the one-off GC in `lib/undo.ts:92-106` already treats every copy as a reference, and the two checks stay the same. An untap copy almost always holds foods that a live meal item or override still references, so the filter would seldom change a result.
- **The 409 message does not change.** It stays "This food is used by your meal plan or past logs and can't be deleted." A saved meal adjustment is part of the log history. Change it only if the owner asks.

## Review Focus

1. **The status-batch case.** The ticket says a status batch has the same hole. `saveReplaced` (`lib/undo.ts:17-37`) fills `food_ids` from the log entries of a status copy and from the override rows of an override copy. The new check reads only `food_ids`, so one check covers both kinds. The test covers the override example only. The reviewer confirms this from `saveReplaced`. No second test.
2. **A food with no references at all** must still delete. The existing test `creates, lists, updates, and deletes a grocery` in `lib/groceries.test.ts` covers this. It must stay green.
3. **The refusal must end when Undo uses the copy.** The new test reverts B and then A, and then deletes X. That delete must succeed.
4. **A non-integer id or an id with no row.** The route already returns 400 for a non-integer id. For an id with no row, the check finds no copy, the delete removes no row, and the route returns `{ ok: true }` as before. No change.
5. **Other 500s.** The route must still rethrow any error that is not an FK violation and not a `FoodInUseError`.

In `lib/overrides.test.ts`, add the imports `createGrocery, deleteGrocery` from `./groceries`, `NextRequest` from `next/server`, and `DELETE` from `../app/api/groceries/[id]/route`. Add this test:

```ts
it("a grocery that only a saved copy references can't be deleted, so Undo restores it", async () => {
  const [f1] = await anyTwoFoods();
  const meal = await firstMeal();
  const x = await createGrocery({
    name: "ZZDEV undo grocery", servingGrams: 100, kcal: 100,
    proteinG: 10, carbsG: 10, fatG: 1,
  });
  try {
    const a = await setMealOverride(DATE, meal.id, [{ foodId: x.id, quantity: 1 }]);
    const b = await setMealOverride(DATE, meal.id, [{ foodId: f1.id, quantity: 1 }]);

    const res = await DELETE(
      new NextRequest(`http://localhost/api/groceries/${x.id}`, { method: "DELETE" }),
      { params: Promise.resolve({ id: String(x.id) }) },
    );
    expect(res.status).toBe(409);
    expect(await db.select().from(foods).where(eq(foods.id, x.id))).toHaveLength(1);

    expect(await revertWriteBatch(b.writeBatchId)).toMatchObject({ reverted: true });
    expect(await linesFor(meal.id)).toEqual([[x.id, 1]]);

    // Once Undo has used the copy and A is gone too, X deletes.
    expect(await revertWriteBatch(a.writeBatchId)).toMatchObject({ reverted: true });
    await deleteGrocery(x.id);
    expect(await db.select().from(foods).where(eq(foods.id, x.id))).toHaveLength(0);
  } finally {
    await cleanup();
    await db.delete(foods).where(eq(foods.id, x.id));
  }
});
```
