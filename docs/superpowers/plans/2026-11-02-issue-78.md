# Remove apply-seed-v2.ts: Issue #78 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** No script in the repo can replace the live plan template with the stale seed template. `db/apply-seed-v2.ts` is deleted, and every live pointer to it is removed.

**Architecture:** Delete the script. Do not guard it. Seed v2 was a one-time migration, and it already ran against live Neon (docs/HISTORY.md, "Seed v2"). The live plan has moved on since then, so the script has no safe job left. Live data changes already follow a better pattern: a one-off script that writes rows by id behind a name guard and runs dry by default (`db/apply-label-data.ts`, #10). The comments that point at the deleted script now point at that pattern. The full-wipe reset (`npm run db:seed`) does not change.

**Tech Stack:** TypeScript, `npx tsx` scripts in `db/`, vitest.

**Spec:** GitHub issue #78 (no design spec, no comments). Done when:
- Running `apply-seed-v2.ts` against the live DB cannot replace the live plan template, or the script is removed.
- STATE.md's gotcha line no longer calls `apply-seed-v2.ts` the safe live-data path.

## Global Constraints

- Do not run the script against live Neon to test it. (Issue constraint. Deleting it means nobody runs it.)
- `npm run db:seed` (full wipe) stays the documented reset path. `db/seed.ts` and `db/seed-data.ts` keep all their data and behavior; only comments change.
- STATE.md changes only in the accept-time docs commit (AGENTS.md). The build does not touch STATE.md.
- `docs/HISTORY.md` and the old plan and spec files under `docs/superpowers/` are archive. They keep their mentions of `apply-seed-v2.ts`. Do not edit them.
- `db/apply-display-qty.ts` is out of scope. It writes only `display_qty` and one rename, and it does not touch `meal_items` or `profile`.

## Gate 1 decisions (most likely to be wrong first)

1. **Delete, not guard.** The other option is to keep the script and make it refuse to run when the live `meal_items` differ from `MEAL_ITEMS_V2`. That option keeps about 90 lines whose only safe run is a no-op, and its food-macro overwrite would still undo label data that the guard does not check. Deletion meets the first Done-when line directly. The `RENAMES` map and the script itself stay in git history.
2. **No new test.** Nothing imports the script, and a test that checks "this file does not exist" pins nothing useful. The proof is the grep in Task 1 Step 3, plus a clean `tsc` and suite.
