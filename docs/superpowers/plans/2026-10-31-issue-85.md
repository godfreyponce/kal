# Undo restores what a replacing write deleted (#85) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Undo on a meal adjustment or status change puts back the state from before that write. Undo on an older card that a newer write replaced is refused, and the card says "Replaced".

**Architecture:** Two writes delete what they replace. `setMealOverride` deletes the meal's override rows for the date, and `setMealStatus` deletes the earlier batch's auto-logged entries and overwrites the one status row. From now on, both writes first copy the rows they are about to remove into one new table, `replaced_writes`, keyed by the new write's batch id. `revertWriteBatch(B)` deletes B's rows (as today), re-inserts the saved rows with their original batch ids, and deletes the saved copy. If a saved copy names B as the replaced batch, B has a newer write on top of it, so revert refuses and changes nothing. No read path changes: replaced rows are not in the live tables, so no read needs a filter.

**Tech Stack:** Next 16 route handler, drizzle-orm 0.45 + drizzle-kit 0.31 on Neon (neon-http, no interactive transactions), vitest against live Neon.

**Spec:** Issue #85 (`gh issue view 85`). The issue has no Done when section. The owner took the planner's recommendations on 2026-10-31 (fix shape (b), Done when below, no design variants), and this plan records those decisions.

## Review Focus

1. **One-off food GC deletes a food that only a saved copy references.** `revertWriteBatch` GCs `one_off` foods that no live row references. A food referenced only by a saved override row would be deleted, and the later restore would then fail on the `food_id` foreign key. The GC must also skip foods in any `replaced_writes.food_ids`. Test in Task 1.
2. **Chain of three writes (A, B, C on one meal).** Undo C restores B. B is then no longer replaced, so undo B restores A. Restored rows must keep their original `write_batch_id` for this to work. Test in Task 1.
3. **Today untap (`pending`) after a chat write.** A pending write has no batch id and no card, but it still deletes the earlier batch. It saves a copy with `batch_id` null, so the older card is refused and does not bring back a state the owner has since cleared. Test in Task 1.
4. **Double tap on Undo.** A second revert of the same batch finds no rows and no saved copy, so it changes nothing and returns `reverted: true` with `revertedEntries: 0`. Test in Task 1.
5. **Stale "Replaced" label in the client.** After undo C, card B is undoable again on the server, but the client has no way to know if it already shows "Replaced". This is accepted for now. A reload clears it. No test, but the gate-2 summary must mention it.

**Interfaces:**
- Produces, in `db/schema.ts`:
  ```ts
  export const replacedWrites = pgTable("replaced_writes", {
    id: serial("id").primaryKey(),
    date: date("date").notNull(),
    mealId: integer("meal_id").notNull().references(() => meals.id, { onDelete: "cascade" }),
    batchId: uuid("batch_id"),                 // the replacing write; null = Today untap (no Undo)
    replacedBatchId: uuid("replaced_batch_id"),// batch of the saved rows
    foodIds: integer("food_ids").array().notNull(),
    rows: jsonb("rows").$type<ReplacedRows>().notNull(),
    createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
  });
  ```
- Produces, in `db/schema.ts` (type) and `lib/undo.ts` (functions):
  ```ts
  export type ReplacedRows =
    | { kind: "override"; overrides: Array<Omit<typeof mealOverrides.$inferSelect, "id">> }
    | { kind: "status"; status: Omit<typeof mealStatus.$inferSelect, "id">;
        logEntries: Array<Omit<typeof logEntries.$inferSelect, "id">> };
  export async function saveReplaced(args: {
    date: string; mealId: number; batchId: string | null; rows: ReplacedRows;
  }): Promise<void>;
  export type RevertResult =
    | { reverted: true; revertedEntries: number }
    | { reverted: false; reason: "replaced" };
  export async function revertWriteBatch(batchId: string): Promise<RevertResult>;
  ```
  `saveReplaced` sets `replacedBatchId` from the saved rows' `writeBatchId` and `foodIds` from every `foodId` in them. It does nothing when there are no rows to save: an empty override list, or no prior status row.
