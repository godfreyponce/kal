# test-gate hook sees same-call staging and ignores quoted text (#87) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `.claude/hooks/test-gate.sh` runs the suite when a code file is staged in the same Bash call as `git commit`, and never gates a command that does not run `git commit`.

**Architecture:** The hook is a PreToolUse hook, so it runs before the Bash command and sees the index as it was before any `git add` in that command. The fix splits the command into its subcommands (one jq program), after it replaces every quoted string with the token `QUOTED`. A subcommand that starts with `git commit` (after optional `VAR=value` assignments) makes the hook act; nothing else does. The arguments of every `git add` / `git rm` / `git mv` subcommand go into the file list beside `git diff --cached --name-only`, and the existing `.md` filter decides. A flag (`-A`), a directory (`.`, `lib/`), or a quoted path (`QUOTED`) does not end in `.md`, so it runs the suite. Wrong guesses go toward running the suite, never toward skipping it.

**Tech Stack:** bash 3.2 (macOS `/usr/bin/env bash`), jq 1.8 (Oniguruma regex), vitest 4.1 (its glob uses `dot: true`, so a test under `.claude/` is collected).

**Spec:** Issue #87 (`gh issue view 87`). No comments, no design spec. Labeled `ready-for-agent`, `Blocked by: none`.

## Planner decisions (gate 1: the owner can change these)

- **Count the staged paths; do not use the "empty stage means run the suite" rule.** The issue offers both. The empty-stage rule is smaller, but it has two problems. First, it makes the accept-time docs commit (`git add STATE.md docs/HISTORY.md && git commit`) pay the full live-Neon run, which the hook header says it must not. Second, it misses a stage that already holds a `.md` file when a `.ts` file is added in the same call. Counting `git add` args has neither problem.
- **No shell evaluation of the args.** The hook does not run `git add --dry-run` with the model's args, because that executes text from the command. The args are read as words. Anything that is not plainly a `.md` path runs the suite.
- **`git rm` and `git mv` count too.** They stage changes the same way as `git add`, so they cause the same bug. Including them adds one regex group: `(add|rm|mv)`.
- **The `if` field in `.claude/settings.json` does not change.** Claude Code checks `if` against each subcommand, so `git add x && git commit` already fires the hook. A `$VAR`, `$()`, or backtick in the command also makes it fire ("patterns that specify more than the command name run the hook anyway on `$()`, backticks, or `$VAR`", code.claude.com/docs/en/hooks). That is how the #84 ledger `printf` got gated, so the script's own check is the one that must be exact.
- **No design variants.** Nothing visual.

## Review Focus

1. **Quoted path in `git add`** (`git add "lib/a b.ts" && git commit`): the path becomes `QUOTED`, which is not `.md`, so the suite runs. Test case 5 in Task 1.
2. **`git add -A` / `git add .` with code changes:** the flag or `.` is not `.md`, so the suite runs. Test case 3 in Task 1.
3. **Multi-line heredoc commit message** (`git commit -m "$(cat <<'EOF' ... don't ... EOF)"`, the harness's default commit form): the double-quoted span is stripped first, so the apostrophe inside it does not break the single-quote strip. The `git commit` subcommand still starts its segment. Test case 7 in Task 1.
4. **`&&` inside a quoted string** (`echo "x && git commit -m y"`): quotes are stripped before the split, so no segment starts with `git commit`. Test case 9 in Task 1.
5. **Known gaps, not fixed here:** `git -C dir commit` and `git commit -- path` (commits named paths that are not staged). The `if` field does not match `git -C`, and the pathspec form existed before this ticket. Name both in the gate-2 summary. No test.

- [ ] **Step 3: Rewrite the gate check in `.claude/hooks/test-gate.sh`**

Keep `INPUT` and `COMMAND` (the `-a/--all` grep still reads `COMMAND`). Replace the `case` block and its comment with the segment split below, then exit 0 unless a segment matches `^([A-Za-z_][A-Za-z0-9_]*=[^[:space:]]*[[:space:]]+)*git[[:space:]]+commit([[:space:]]|$)` (`grep -Eq`). The jq program was checked in a scratch run against all nine rows. Keep its escapes exactly: `\\x27` is the single quote, which cannot appear inside the bash single-quoted string, and the double-quote strip must run before the single-quote strip.

```bash
SEGMENTS_JQ='.tool_input.command // ""
  | gsub("\"(\\\\.|[^\"\\\\])*\""; " QUOTED ")
  | gsub("\\x27[^\\x27]*\\x27"; " QUOTED ")
  | gsub("&&|\\|\\||[;|&()`\n]"; "\n")
  | split("\n")[]
  | sub("^\\s+"; "")'
SEGMENTS=$(printf '%s' "$INPUT" | jq -r "$SEGMENTS_JQ")
```
