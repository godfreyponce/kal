# Harden the Anthropic API key: Issue #80 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The one module that builds the Anthropic client and reads `ANTHROPIC_API_KEY` imports `server-only`, so a client-side import of it fails the Next build instead of shipping the key to the browser. The Console and Vercel steps that cap a leaked key's damage are listed for the owner.

**Architecture:** `getAnthropic()` moves out of `lib/anthropic.ts` into a new `lib/anthropic-client.ts` that starts with `import "server-only"`. `lib/anthropic.ts` keeps the model ids, the price table, `usageCostUsd`, and `withoutThinking`: none of them read the key. Vitest aliases `server-only` to the package's empty module, because the package's default export throws outside a React Server bundle.

**Tech Stack:** Next 16.2.9 (Turbopack), `server-only` npm package, vitest, `npx tsx` scripts.

**Spec:** GitHub issue #80 (no design spec in `docs/superpowers/specs/`). Not labeled `ready-for-agent`; the owner typing `/run-ticket 80` is the green light.

## Decisions for gate 1

1. **The key read moves to a new file instead of putting `server-only` in `lib/anthropic.ts`.** The ticket's Done-when names `lib/anthropic.ts` because that is where the key is read today. But `lib/spend.ts` imports `CHAT_MODEL`, `FALLBACK_CHAT_MODEL`, and `usageCostUsd` from it, and `scripts/spend.ts` imports `lib/spend.ts` under plain `npx tsx`. Outside Next, `import "server-only"` resolves to the package's `index.js`, which throws. So the literal reading breaks `npx tsx scripts/spend.ts`, the command the #63 owner check in STATE.md's Now still owes. With the split, the module that reads the key carries the guard, and nothing the script needs imports it. The rejected alternative: keep the guard in `lib/anthropic.ts` and run the script as `npx tsx --conditions=react-server scripts/spend.ts`. That changes the owner's command and depends on a Node resolve condition no one has tested on this graph.
2. **No new automated test for the guard.** A test that greps for the import would test the code's shape, not its behavior, and a test that runs `next build` is too slow for the suite. The proof is a one-off negative build at gate 2 (Task 1, Step 7): put in a temporary client import, see the build fail, revert, paste the output.
