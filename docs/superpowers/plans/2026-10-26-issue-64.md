# Chat on Opus 5.5 with a monthly spend guard (Sonnet 5.5 fallback): Issue #64 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The in-app chat answers on `claude-opus-5-5` with adaptive thinking at low effort. When cycle-to-date spend from #63's ledger reaches an env threshold, it answers on `claude-sonnet-5-5` instead, and the chat header shows the model that answered. Label reading is pinned to `claude-haiku-4-5`.

**Architecture:** The model is picked once per chat request by a new `currentChatModel()` in `lib/spend.ts`. It reads `monthToDateSpendUsd()` (#63) and compares the total to `SPEND_FALLBACK_USD`. The route uses that one model for the whole tool loop, so the loop never switches models mid-turn. Within a turn, the route passes each assistant `final.content` back unchanged, thinking blocks included, as it does today. When the route loads earlier turns from `chat_messages`, it strips their thinking blocks (see Decision 1). The route sends a new `{ type: "model" }` event, and the chat page renders the model that will answer.

**Tech Stack:** Next 16 App Router, `@anthropic-ai/sdk` 0.105.0 (already has `ThinkingConfigAdaptive` and `OutputConfig.effort`, so no SDK upgrade), Drizzle on Neon, vitest.

**Spec:** GitHub issue #64 (no design spec in `docs/superpowers/specs/`). Model decision: #62 Q14, 2026-10-08.

## Decisions for gate 1 (most likely to be wrong first)

1. **Earlier turns go back without their thinking blocks.** Opus 5.5 and Sonnet 5.5 bind each thinking block's signature to the exact conversation prefix: the `system` prompt, the `tools`, and every earlier message. The claude-api skill (`shared/model-migration.md`, preserved thinking, breaking change 3) lists "rebuilding the top-level `system` prompt between requests in the same conversation" as an edit that invalidates every later block. On orgs created on or after 2026-08-31, the API answers that edit with a 400. Kal rebuilds the dynamic system block (today's numbers) on every POST, and it trims the history head at `HISTORY_CAP`. Both break the binding across turns. The same doc says that "removing a *leading* run of thinking blocks" keeps later blocks valid. So: `chat_messages` keeps every block unchanged. Inside one request's tool loop, the route replays the blocks unchanged, and `system` stays fixed for that request. `loadHistory` strips `thinking` / `redacted_thinking` from earlier turns. The cost: the model does not see its own earlier-turn reasoning. Its earlier text and tool calls stay. *Alternative:* freeze `system` per session, move the per-day numbers into appended `role: "system"` messages, and replace head-trimming with server compaction. That is a much bigger change, so file it as its own issue if wanted.
2. **A missing or bad `SPEND_FALLBACK_USD` means Sonnet, not Opus.** If the env is unset, empty (the `vercel env pull` trap), or not a positive number, the guard cannot work. Falling to the cheaper model shows up at once in the chat header ("claude-sonnet-5-5"), so a forgotten env var is visible and costs less. *Alternative:* unset means Opus with no guard. Then the chat stops when the credit runs out, which is the failure this ticket exists to prevent.
3. **`MAX_TOKENS` becomes `64_000`.** Source: the claude-api skill's default for streaming requests ("For streaming requests, default to ~64000"). Opus 5.5 and Sonnet 5.5 allow 128K output. The route already streams, so a large cap has no timeout cost, and billing counts only the tokens used. The thinking and the reply share this cap. Low effort keeps the real use far below it.
4. **`maxDuration` becomes `300`.** Source: Vercel's duration table (vercel.com/docs/functions/configuring-functions/duration, fluid compute on by default): Hobby default and maximum are 300 s, and Pro's default is 300 s. Opus latency cannot be measured before the build, because the local `ANTHROPIC_API_KEY` is `""`. 300 is the highest value valid on every plan. The live check at gate 2 shows whether an 8-iteration turn fits.
5. **The `ANTHROPIC_MODEL` env override goes away.** With the guard choosing between two fixed models, an override would bypass both the done-when and the guard. If `ANTHROPIC_MODEL` is still set in Vercel, it becomes unread and harmless. The owner may delete it.
6. **No server-side refusal `fallbacks`.** The claude-api skill turns `fallbacks: "default"` on by default for Opus 5.5 code. The ticket does not ask for it, and it moves the call to `client.beta.messages` with beta types. A refusal today ends the turn without a crash. If the owner wants it, file a follow-up issue.
7. **Not a visual ticket.** The header label already exists. Only its text changes, so no design variants are made.

## Global Constraints

- The threshold lives in env only (`SPEND_FALLBACK_USD`). **No real amount in the repo** (public). Test values are arbitrary.
- No new dependency. The installed SDK 0.105.0 already types `thinking: { type: "adaptive" }` and `output_config: { effort: "low" }`.
- Server `web_search` / `web_fetch` are #56, not this ticket.
- Opus 5.5: `thinking: { type: "disabled" }`, `budget_tokens`, and forced `tool_choice` all return 400. Send `thinking: { type: "adaptive" }` and `output_config: { effort: "low" }` explicitly, because Opus 5.5's default effort is `medium`. The same params are valid on Sonnet 5.5.
- Label reading behaves as today (Haiku 4.5, no thinking params). The pin is the only change.
- The worktree has no `node_modules`. Run `npm ci` before the first test.
- Commit format (AGENTS.md `# Commit format`): `type(scope): summary (refs #N)`. Trailers: the harness default `Co-Authored-By` line, nothing else. This plan has several tasks, so the build makes one commit per approved task on the ticket branch (`t3/rt-64`).
- While iterating, run only the touched test files (`npx vitest run lib/foo.test.ts`). The full check runs once at the end.

## Review Focus

1. **A turn that hits refusal or ends with no blocks.** An assistant row with `content: []` lands in `chat_messages`. Replaying an empty assistant message on the next turn is a 400. `withoutThinking` drops any assistant message whose array content is empty, so the turn after still works. The Task 2 test pins this.
2. **An assistant turn that held only thinking + `tool_use`.** After stripping, the `tool_use` must stay, with its paired `tool_result` turn after it. The Task 2 test pins this.
3. **Threshold exactly equal to the spend.** "Reaches" means `>=`, so it falls back. The Task 1 tests pin below, at, and above.
4. **`SPEND_FALLBACK_USD=""`** (left by an env pull). It counts as missing, so the chat uses Sonnet. The Task 1 test pins this.
5. **Spend crossing the threshold mid-turn.** The model is picked once per request, so the turn finishes on the model it started with. Covered by design: `currentChatModel()` is called once, before the stream. The Task 2 code step pins where.
